## 驱动框架

### 设备核心层

- 关键文件

  - `device_core.h`和`device_core.c`

- 说明

  - ops：包含初始化、读、写和ioctl函数

  - 通知回调：`typedef void (*device_notify_t)(struct device *dev, uint32_t event);`

    - 用做裸机、RTOS的合并处理
    - 通过 `DEV_IOCTL_SET_NOTIFY` 命令设置，驱动在中断等场景中主动调用，通知上层事件

  - 关键API

    - ```c
      int 			device_register	(struct device *dev);
      struct device*	device_find		(const char *name);
      int				device_init		(struct device *dev);
      int 			device_read		(struct device *dev, void *buf, size_t len);
      int				device_write	(struct device *dev, const void *buf, size_t len);
      int				device_ioctl	(struct device *dev, int cmd, void *arg);
      ```

  - 返回值：成功返回 `0`，失败返回 `-1`（设备未找到、ops或函数指针为空等情况）

  - 设备注册上限：最多 `16` 个设备（`MAX_DEVICE_NUM`）

  - `struct device` 关键字段

    - `name`：设备唯一标识，用于 `device_find` 查找
    - `ops`：操作函数集，同一类驱动可共用
    - **`priv`**：驱动私有数据指针，存放硬件句柄、引脚号等，这是驱动开发的核心
    - `notify`：通知回调

  - `ioctl_cmd.h`

    - 不同外设的命令在不同的前8bit设置
    - 通用命令在`0x0000`到`0x00FF`
    - 当前已定义：`DEV_IOCTL_RESET`（0x0001）、`DEV_IOCTL_SET_NOTIFY`（0x0002）
    - **低字节从0x01开始编号，0x00保留不使用**

  - 驱动注册在`board_init`函数中调用

### 设备驱动层

- 关键文件
  - `xxx_driver.c`
- 说明
  - 不需要头文件，只需要实现实例即可
  - 设备实例声明为`static`，外部不可见，通过`device_find`按名称访问
  - 驱动导出`xxx_driver_init()`入口函数，内部完成`device_register`和`device_init`
  - 注释统一使用英文
  - 硬件操作只使用Xilinx BSP API（如`XGpioPs_WritePin`/`ReadPin`），禁止直接访问寄存器

- 驱动文件结构（4段式）

  1. **Includes和私有数据**

     ```c
     extern XGpioPs g_gpio_ps;  /* defined in board_init.c */

     struct xxx_priv {
         XGpioPs  *gpio;   /* 硬件控制器句柄，静态初始化时写死 */
         uint32_t  pin;
         uint8_t   state;
     };
     ```

  2. **device_ops函数实现**

     ```c
     static int xxx_init(struct device *dev)  { /* 通过priv->gpio调用Xilinx API */ }
     static int xxx_read(struct device *dev, void *buf, size_t len)   { /* ... */ }
     static int xxx_write(struct device *dev, const void *buf, size_t len) { /* ... */ }
     static int xxx_ioctl(struct device *dev, int cmd, void *arg) { /* ... */ }
     ```

     不需要的ops置`NULL`

  3. **ops和device实例**

     ```c
     static const struct device_ops xxx_ops = { .init = xxx_init, ... };

     static struct xxx_priv xxx0_priv = { .gpio = &g_gpio_ps, .pin = 0 };
     static struct device g_xxx0 = {
         .name = "xxx0", .ops = &xxx_ops, .priv = &xxx0_priv, .notify = NULL,
     };
     ```

  4. **驱动入口函数**

     ```c
     void xxx_driver_init(void)
     {
         device_register(&g_xxx0);
         device_init(&g_xxx0);
     }
     ```

### board_init层

- 关键文件
  - `board_init.c`

- 说明
  - 定义硬件控制器全局实例（如`XGpioPs g_gpio_ps`），各驱动通过`extern`引用
  - 每个控制器的初始化封装为`static`函数（如`gpio_ps_init()`）
  - `board_init`函数中依次调用：控制器初始化 → 各驱动的`xxx_driver_init()`
  - 不需要`extern`任何`struct device`实例

- 示例

  ```c
  XGpioPs g_gpio_ps;

  extern void led_driver_init(void);
  extern void key_driver_init(void);

  static void gpio_ps_init(void)
  {
      XGpioPs_Config *cfg = XGpioPs_LookupConfig(XPAR_PS7_GPIO_0_DEVICE_ID);
      XGpioPs_CfgInitialize(&g_gpio_ps, cfg, cfg->BaseAddr);
  }

  void board_init()
  {
      gpio_ps_init();
      led_driver_init();
      key_driver_init();
  }
  ```

### 新增驱动开发步骤

1. 在 `ioctl_cmd.h` 中定义该外设的 ioctl 命令（前8bit区分外设类型，低字节从0x01起编）
2. 创建 `xxx_driver.c`，按4段式实现：
   - 定义 `xxx_priv` 结构体，包含硬件控制器指针（`gpio`）和设备参数（`pin`、`state`等）
   - 实现 `device_ops` 的四个函数（`init`/`read`/`write`/`ioctl`），不需要的置 `NULL`
   - 定义 `device_ops` 实例和 `xxx_priv` + `struct device` 实例（均为`static`）
   - 定义 `xxx_driver_init()` 入口函数，内部完成注册和初始化
3. 在 `board_init.c` 中 `extern` 该驱动的入口函数，在`board_init`中调用

### 应用层使用

- 通过 `device_find("设备名")` 获取设备指针
- 调用 `device_read`/`device_write`/`device_ioctl` 进行操作
- 需要异步通知时，通过 `device_ioctl(dev, DEV_IOCTL_SET_NOTIFY, &callback)` 注册回调
- 不需要`extern`任何设备实例，全部通过`device_find`按名称访问
