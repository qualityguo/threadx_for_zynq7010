## 第一章：操作系统移植（基于版本6.4.1）

### 一、项目工程结构

- `BSP`：外设驱动代码
- `ThreadX/Source`：存储操作系统源码
- `ThreadX/Port`：操作系统的移植层
- `ThreadX/utility`：相关组件
- `main.c`：任务管理文件
- `includes.h`：头文件汇总
- `ThreadX`
  - `tx_port.h`：移植头文件
  - `tx_user.h`：ThreadX配置文件


### 二、代码拷贝

- `/threadx/common/inc/`到`ThreadX/Source`目录下
- `/threadx/common/src/`到`ThreadX/Source`目录下
- `/threadx/ports/cortex_a9/gnu/src/*`到`ThreadX/Port`目录下（拷贝文件）
- `/threadx/ports/cortex_a9/gnu/inc/tx_port.h`到根目录下的`ThreadX/tx_port.h`
- `/threadx/ports/cortex_a9/gnu/example_build/*.h&*.S`到`ThreadX/Port`目录下（拷贝文件）
- `/threadx/utlity/execution_profile_kit/*.s&*.c`到`ThreadX/utlity/execution_profile_kit/`目录下（拷贝文件）

### 三、代码修改

- `lscript.ld`中修改

  - ```
    + _sp = __undef_stack;
    + _stack_bottom = _stack_end;
    
    _end = .;
    ```

  - 将应用控制权交给ThreadX之后，重设栈指针

- `tx_user.h`中参考`/threadx/common/inc/tx_user_sample.h`

  - 加入宏`#define TX_ENABLE_FIQ_SUPPORT`
  - 加入宏`#define TX_EXECUTION_PROFILE_ENABLE`

- 修改`ThreadX/Port/v7.s`名称为`ThreadX/Port/v7.S`

- 删除`ThreadX/Port/crt0.S`

- 修改`reset.S`中的文件向量表的位置

  - ```c
    // 将__vectors中断向量表放在vectors段中，xilinx的BSP对应的_vector_table后边
    .section .vectors, "ax"
    .align 5
    .global __vectors
    ```

  - 否则会应为向量表地址不对齐造成异常中断

- 修改`tx_initialize_low_level.S`

  - ```c
    # _tx_initialize_low_level函数入口保存lr
    MOV		r12, lr
    # PUSH lr的时候替换为PUSH r12    
    PUSH	{r12}								// Push saved return address(in r12)
    ```

- bsp文件夹中加入函数`bsp_init`，在`includes.h`包含，在`main`函数中调用

  - 其中完成GTC的初始化（我们采用32bit的计数器做性能评估）

  - ```c
    #define GTIMER_COUNTER_LO   (*(volatile u32 *)0xF8F00200)
    #define GTIMER_COUNTER_HI   (*(volatile u32 *)0xF8F00204)
    #define GTIMER_CONTROL      (*(volatile u32 *)0xF8F00208)
    
    /* 只使用1个32bit的值用作性能测试 */
    static void Global_Timer_Init()
    {
    	GTIMER_CONTROL    = 0x00;
    	GTIMER_COUNTER_LO = 0;
    	GTIMER_COUNTER_HI = 0;
    	GTIMER_CONTROL    = 0x01;
    }
    
    void bsp_init()
    {
    	Global_Timer_Init();
    }
    ```

- `includes.h`加入头文件，`#include "bsp_init.h"`

  - ```c
    extern EXECUTION_TIME     _tx_execution_thread_time_total;
    extern EXECUTION_TIME     _tx_execution_isr_time_total;
    extern EXECUTION_TIME     _tx_execution_idle_time_total;
    ```

## 第二章：系统启动相关分析

### 一、Xilinx的启动流程

- 关键的几个文件
  - `asm_vectors.S`
  - `boot.S`
  - `cpu_init.S`
  - `translation_table.S`
  - `xil-crt0.S`
- 初始化流程（以单核CPU0为例）
  - 上电后执行`_boot`函数，位于异常向量表的首地址
  - 执行`CheckEFUSE`函数，做了一些检查后跳转`OKToRun`
  - `OKToRun`
    - 处理两个BUG
    - 设置VBAR
    - 无效化缓存和TLB
    - 禁用MMU
    - 设置处理器各种模式的栈指针
    - 使能SCU
    - 使能MMU
    - 配置ACTLR
    - 初始化并使能L2Cache
    - 使能p10和p11的全访问
    - 使能FPU
    - 使能分支预测和预取址
    - 使能异步中断异常
    - 跳转`start`
  - `start`函数
    - 执行`__cpu_init`，清空cp15中复位值未知的寄存器，复位并启动周期计数器
    - 清SBSS段
    - 清BSS段
    - 设置System模式的栈指针
    - 初始化一个全局定时器
    - 跳转`main`

### 二、ThreadX移植层文件的启动流程

- 关键的几个文件
  - `reset.S`
  - `crt0.S`
  - `tx_initialize_low_level.S`
- 初始化流程
  - 异常向量在异常向量表中的顺序和裸机环境下是一致的
  - 上电后会执行`_start`
  - `_start`函数
    - 初始化SP
    - 设置栈限制寄存器SL
    - 清零栈指针
    - 清零BSS段
    - 跳转`main`
  - `main`函数
    - 调用`tx_kernel_enter`
    - 调用`tx_initialize_kernel_enter`
    - 调用`_tx_initialize_low_level`
    - 调用一些初始化后进入一个调度器
  - `_tx_initialize_low_level`函数
    - 设置处理器各种模式的栈指针，SYS模式、FIQ模式、IRQ模式
    - 计算可用内存
    - 设置中断向量表
    - 初始化GIC
    - 设置中断优先级
    - 配置私有定时器中断
    - 使能SGI
- 不同对比
  - 栈空间设置（复用栈空间）
    - 裸机环境下的栈空间
      - SYS模式栈：8KB
      - IRQ模式栈：1KB
      - SVC模式栈：2KB
      - Abort模式栈：1KB
      - FIQ模式栈：1KB
      - UBDEF模式栈：1KB
    - ThreadX环境下的栈空间
      - SVC栈：12.5KB
      - IRQ栈：1KB
      - FIQ栈：0.5KB
